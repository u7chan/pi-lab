# 本番 OSS への移行方針

`pi-lab` で検証した拡張を、自分の常用環境向けの本番 OSS に移行するための合意事項です。
本番用リポジトリ [mypi](https://github.com/u7chan/mypi) は作成済みです。
対象６機能を移植し、対応するテストと Pi 1.0.0 上の隔離検証を完了しました。
常用環境の Pi package は mypi に切り替え済みです。pi-lab の配布 manifest・元コードは維持します。

## 目的

- 自分の常用環境を安定させ、その構成を OSS として公開する。
- インストール・更新・リリースの管理を 1 つにまとめる。
- Pi 起動時の Extensions 欄で、本番版の拡張セットを 1 項目として表示する。
  他の外部拡張の表示は変更しない。

他人向けの汎用拡張集として育てることは、今回の要件に含めません。

## 確定事項

### 公開・配布

- `pi-lab` とは別の Public リポジトリで公開する。
- 1 つの Pi package として配布する。
- npm には公開しない。
- `pi.extensions` に登録する入口も 1 つにする。
- 現在の登録済み 6 機能をすべて有効にする。機能別 ON/OFF 設定は作らない。

現在の `pi-lab` は 1 パッケージに複数の拡張を登録しているため、パッケージをまとめるだけでは
Extensions 欄の項目数は減りません。本番版では入口もまとめます。

### 内部構成・保守

- 入口は各機能の登録処理を呼ぶだけにし、巨大な 1 ファイルに統合しない。
- コード・状態・テストの境界は機能別に保つ。
- AI による保守を前提にしても、変更の影響範囲と検証対象を限定できる境界は残す。
- 機能ごとの独立パッケージ化や、汎用的なプラグイン機構は作らない。

配置例（ファイル名の確定ではありません）:

```text
extensions/index.ts    # Pi に登録する唯一の入口
src/<機能>/            # 機能別の実装
tests/<機能>/          # 機能別のテスト
```

### 言語・性能

- TypeScript を継続する。本番化に合わせた Rust / Go への移植は行わない。
- 実測で遅い部分が見つかった場合だけ最適化する。
- Rust / Go への部分移植は、その時点で必要なら検討する。

確認した Pi 1.0.0 の拡張の入口は TypeScript / JavaScript モジュールです。
Rust / Go の実行ファイルを使う場合も、Pi 接続用の TS / JS とバイナリ配布などの保守が増えます。
現在の 6 機能について、言語移植を必要とする性能問題は実測で確認していません。

## 移行対象

合意時点の対象は次の 6 機能です。新しい PoC が登録されても、自動的には対象に追加しません。

- `u7chan-lab-cache-ttl`
- `u7chan-lab-cache-savings`
- `u7chan-lab-minimal-footer`
- `u7chan-lab-default-model`
- `u7chan-lab-git-status`
- `u7chan-lab-elapsed`

未登録の `u7chan-lab-skill-dispatch` は今回の移行対象外です。

## 移行状況の管理

[ルート README の PoC 一覧](../README.md#poc-一覧)の「移行状況」列で、機能ごとに管理します。

| 状態 | 意味 |
|---|---|
| 未移行 | 今回の移行対象だが、本番リポジトリへの移行は完了していない |
| 移行済み | 本番リポジトリへの移植と、対応するテスト・Pi 上の動作確認が完了した |
| 対象外 | 今回の移行対象に含めない |

- 機能ごとに移行を完了した時点で、README の該当行を「移行済み」に更新する。
- 本番リポジトリを作成したら、この文書に移行先へのリンクを記載する。
- 「配布」は `pi-lab/package.json` の登録状況、「移行状況」は本番版への移行状況として分ける。
  移行済みになっただけで、`pi-lab` の配布状態やコードを自動的に変更しない。
- `pi-lab` 側の配布停止・コードの削除や保持は、実際の移行時に別途判断する。

本番版では、起動時の Extensions 欄が 1 項目になり、対象の 6 機能が従来どおり動作することを
確認します。

## 移行先・確認範囲

- リポジトリ・Pi package 名: `mypi`。
- 公開ライセンス: MIT（`Copyright (c) 2026 u7chan`）。
- 移行先: [u7chan/mypi](https://github.com/u7chan/mypi)。入口は `extensions/index.ts` の１件。
- 対象６機能の移植済みテストと単一入口の統合テストを実行した。
- 実際の Pi 1.0.0 SDK と regular / fullscreen 対話 TUI で、単一入口のロード、表示の共存、
  コマンド・ツール、retry を含む elapsed、後始末を確認した。settings 保存は一時 agent directory のみ。
- provider はローカル mock、PR ありの表示は git/gh fixture で確認した。
  実 provider、実 GitHub PR の取得、端末のリンククリック、常用外部拡張との組み合わせは未検証。
- 詳細・再現手順: [mypi の移行記録](https://github.com/u7chan/mypi/blob/main/docs/migration.md)。
- 常用環境の切り替え: `pi remove git:github.com/u7chan/pi-lab@main` →
  `pi install git:github.com/u7chan/mypi@main`。インストール済み mypi の隔離 smoke は成功した。
  常用環境での実利用確認は別途行う。

## 保留

- Git 配布の更新確認（`pi update --extensions`）、常用環境での実利用確認。
- `pi-lab` の配布 manifest・元コードは維持する。配布停止は別途判断する。
- 機能別 ON/OFF、他人向けの汎用化、未登録 PoC の追加、Rust / Go への部分移植は必要になるまで保留。

## 残る注意点

入口が 1 つになるため、入口や import のエラーで全機能をロードできなくなる可能性があります。
内部の機能分割はプロセス分離ではありません。機能別の境界とテストを残し、本番版の入口を通した
ロードも確認します。
